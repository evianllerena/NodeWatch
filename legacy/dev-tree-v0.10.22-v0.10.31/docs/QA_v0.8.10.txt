Startup-reliability changes verified in source/build:
- backend uses the version-scoped private runtime python.exe with CREATE_NO_WINDOW rather than pythonw.exe;
- stdout/stderr are redirected to NodeWatch\\logs\\backend-launcher.log;
- PYTHONUNBUFFERED and Python faulthandler are enabled for startup diagnostics;
- Python 3.12 is preferred first on Windows because that interpreter family previously ran NodeWatch successfully on the target PC;
- the fresh 256-bit nonce + exact version/build is authoritative for launcher/backend handoff;
- Windows process-image lookup remains diagnostic and can no longer reject an otherwise nonce-verified backend;
- native-launcher.log records backend exit status and points to backend-launcher.log when startup fails.

Build-environment limitation:
The exact pinned Windows runtime wheel set cannot be executed inside this Linux build environment. The shipped Windows launcher was cross-compiled and the Python application was live-smoke-tested in the available environment. The first Windows launch remains the final platform-specific validation.

Supply-chain limitation:
The exact dependencies are pinned and source builds are blocked, but the first-run wheel set is not yet vendored. The stronger future release model remains an offline wheelhouse installed with --no-index --require-hashes.

Windows signing limitation:
NodeWatch.exe is unsigned in this package because no trusted BWN signing identity is present in the build environment. SmartScreen may continue to show Unknown publisher until the final executable is signed with the real BWN identity.
